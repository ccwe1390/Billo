## 2. Architecture & policy findings (outrank section 7)

### B1. Home ("All bills from this visit") with more than one policy
/household always uses VUMC and the 5 VUMC demo bills (main.py:618). A user's Ascension bill is listed
as "Different hospital", but reminders, the .ics file, the phone and "One approval may cover all N
bills" are VUMC's. N counts the uncounted row too (app.js:921). Options:
- (a) hide Home's reminders, calendar and approval line unless the user's own bill matches the Home
  policy (XS);
- (b) evaluate Home with the user's bill's policy and no demo bills when it is not VUMC (S);
- (c) hide the Home button for non-VUMC results (XS).
Question: (a), (b) or (c)?

### B2. A bill with no hospital name
The hospital name is optional (app.js:183 requires only the statement date and amount). A blank name
gives matched = None, so the result uses the VUMC default with no warning (engine.py:91-92, :108-109).
Options:
- (a) make hospital_name required in the UI and engine (XS; a blurred name then blocks until typed);
- (b) treat a missing name like no policy: warning plus help card (XS);
- (c) keep the estimate but show "We could not read the hospital; this uses VUMC's policy" (S).
Question: (a), (b) or (c)?

### B3. Still open from audit 3: A1 (the number lock checks numbers as a set) and A2 ("nothing is
stored" vs the Apache access log). C3 adds one point to A1: the raw hospital name flows into the /explain
prompt, and the lock cannot catch a non-numeric false claim (finding 13).
